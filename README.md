**Тип размещения.** Сервер Бориса — **galaxy-приложение** (`kind: "GALAXY_APP"`), контейнер на
общем хосте-галактике, а не отдельная виртуальная машина. Это подтверждено кодом деплоя в этом
README (`source.content` + `runtime`/`start`/`port`, без ожидания `blackholeStatus: CONNECTED` —
именно так и деплоятся galaxy-приложения, см. ниже). Из этого следует несколько практических
следствий, которые НЕЛЬЗЯ игнорировать при работе с сервером:

- **Постоянные данные — только в `/data`.** Рабочая директория контейнера — `/opt/app`
  (`/app` — симлинк на неё), но она **не персистентна между деплоями**. Постоянный том — `/data`.
  Бот уже это соблюдает: `DATA_DIR = process.env.DATA_DIR || '/data'` в `index.js`, туда пишутся
  `settings.json` (включая `sourceHealth`, `recentlySentHeadlines` из спринта 6). **Если DATA_DIR
  когда-нибудь придётся поменять — только на путь внутри `/data`, никогда не на `/opt/app`.**
- **У galaxy-приложения нет своего SSH, публичного IP и `blackholeStatus`, который доходит до
  `CONNECTED`.** Диагностика через `ssh`/`ip`/ожидание `CONNECTED` из общих доков по инфраструктуре
  к этому серверу неприменима — это путь для отдельных VM (`kind: "STANDALONE"`), не для нас.
- **Исходящий IP не статический** и общий с другими приложениями на той же галактике. Если
  когда-нибудь понадобится добавлять внешний сервис с allowlist по IP (платёжный шлюз, внешняя
  БД) — статического адреса дать нельзя, нужен другой механизм (токен/подпись запроса).
- **Сон и пробуждение — через хост галактики, не через `/sleep`/`/sleep-now`/`/port`.** Эти три
  вызова на galaxy-приложении отвечают `400 GALAXY_APP_USE_GALAXY_ROUTE` — их вызывать бессмысленно.
  Подтверждает то, что уже написано ниже в «Важные особенности архитектуры»: сон отключить нельзя.
- **Wake-расписание для galaxy-приложений может быть выключено отдельно от обычных серверов.**
  Документация прямо предупреждает: `POST .../wake-schedules` на galaxy-приложении может вернуть
  `403 WAKE_SCHEDULE_GALAXY_DISABLED`, даже если для standalone-серверов эта возможность включена
  на портале — «её включают отдельно». **Если утренний дайджест вдруг перестанет приходить по
  расписанию — первым делом проверить именно это**, прежде чем чинить код бота: возможно, окно
  пробуждения на портале не смогло создаться или было отключено платформой, а не багом в
  `index.js`. Явной проверки этого при старте бот сейчас не делает (см. «Что стоит проверить»).
- **`POST /:id/exec` на galaxy-приложении не принимает `workdir`/`env`** — только сама команда с
  явным `cd /opt/app; ...` в начале. Актуально, если когда-нибудь понадобится разовая ручная
  команда на сервере (например, поправить `settings.json` вручную) — писать
  `cd /opt/app && cat /data/settings.json`, а не полагаться на `workdir`.

**Bot API v2 — соответствие кода документации.** Проверено построчно против
[`/docs/bots`](https://vibecode.bitrix24.tech/docs/bots):

- ✅ Опрос событий (`GET /v1/bots/:botId/events?offset=...`), разбор `nextOffset`, обработка
  `ONIMBOTV2MESSAGEADD` через `data.chat.dialogId`/`data.message.text` и `ONIMBOTV2COMMANDADD`
  через `data.command.command`/`data.command.params` — всё **точно по документированному контракту**.
- ✅ Отправка сообщений (`POST /v1/bots/:botId/messages`, тело `{ dialogId, fields: { message,
  keyboard } }`) — совпадает с документированным форматом.
- ✅ Клавиатура — используемые поля кнопки (`TEXT`, `ACTION`, `ACTION_VALUE`, `BG_COLOR_TOKEN`,
  `DISPLAY`) все входят в документированный набор; плоский массив без вложенности — верно
  (вложенные массивы дают `422 BITRIX_ERROR`, это уже отмечено в README ниже).
- ⚠️ **Не используется, но документировано и может пригодиться:**
  - `TYPE: "NEWLINE"` — явный перенос строки в клавиатуре, вместо того чтобы полагаться только на
    `DISPLAY: "LINE"` vs `BLOCK`.
  - `BLOCK: "Y"` — деактивирует кнопку сразу после нажатия. Стоило бы поставить на кнопки
    `/feedback good`/`/feedback bad`, чтобы нельзя было случайно отправить оценку дважды подряд
    одним и тем же тапом на медленной сети.
  - `LINK` — кнопка-ссылка (сейчас не нужна, все действия бота идут через `/команды`).
  - `imbot.v2.Chat.Message.Reaction.add` (`POST /messages/:messageId/reactions`) и событие
    `ONIMBOTV2REACTIONCHANGE` — бот **не ставит и не слушает реакции вообще**. Это прямо
    релевантно спринту 7 (per-story feedback): реакция на конкретное сообщение с конкретной
    историей — более естественный документированный механизм, чем кнопки под всем дайджестом
    целиком, и стоит рассмотреть как альтернативу в планировании спринта 7.
- ❌ **Не сделано вообще: регистрация бота и его команд.** Нигде в `index.js` нет вызова
  `POST /v1/bots` (`imbot.v2.Bot.register`) или `POST /v1/bots/:botId/commands`
  (`imbot.v2.Command.register`). Бот работает только потому, что `BOT_ID` — уже
  где-то зарегистрированный идентификатор (задан через env/дефолт `1505555`), и который сам код
  никогда не создавал и не может пересоздать. Практическое следствие: `/news`, `/settings` и
  остальные команды **не показываются в нативном `/`-пикере команд Битрикс24** (как это сделано
  для `/ping`/`/help` в официальном Echo-bot примере из документации) — пользователь может
  вызвать их только набрав текст руками. Это не баг (бот и так исправно отвечает на введённый
  текст), но это осознанный пробел относительно того, что предлагает платформа, и стоит решить,
  нужна ли регистрация команд как отдельная задача.

## Свободный ввод (живость)

Борис понимает обычные сообщения и живо отвечает (по-русски и по-португальски):

- «Что ты умеешь?», «Кто ты?», «Расскажи о себе» → рассказ о себе и функциях + кнопки
- «Привет», «Добрый день» → живое приветствие, обращается по имени
- «Как дела?», «Как настроение?» → живо отвечает
- «Спасибо», «Круто», «Молодец» → благодарит
- «Пока», «До встречи» → прощается

Не распознанное сообщение → интерактивное приветствие-меню со всеми действиями.

## Важные особенности архитектуры

1. **Сон сервера:** galaxy-приложение засыпает через 60 минут простоя. Пока спит — бот не отвечает. Webhook НЕ решает (спящий сервер не получит событие). Сон отключить нельзя (`GALAXY_APP_USE_GALAXY_ROUTE`). Единственный способ отвечать всегда — перенос на отдельный сервер (VM).
2. **Утренний дайджест:** сервер просыпается по расписанию в 09:00 Мск Пн-Пт. Приложение стартует и в будний день сразу отправляет дайджест (без привязки к узкому окну времени — см. ниже).
3. **Персистентные настройки:** сохраняются в `/data/settings.json` (постоянный том). `loadSettings()` объединяет дефолтные темы с сохранёнными (новые дефолтные темы добавляются).
4. **Клавиатура:** плоский массив кнопок с `DISPLAY: "LINE"` (НЕ вложенные массивы — иначе 422 BITRIX_ERROR).
5. **Wake-расписание galaxy-приложений может быть отключено отдельно от обычных серверов
   на уровне платформы** (`403 WAKE_SCHEDULE_GALAXY_DISABLED`) — независимо от того, работает
   ли эта возможность для standalone VM на этом же портале. Подробности и что проверять первым
   делом, если утренний дайджест перестал приходить, — раздел «Инфраструктура Вайбкод» выше.

## Утренний дайджест

Сервер просыпается по расписанию в 09:00 Мск Пн-Пт. При старте в будний день (Мск) приложение сразу отправляет утренний дайджест пользователю — без привязки к узкому окну времени. Это надёжно, потому что сервер и так просыпается только по расписанию: не нужно полагаться на точное время старта контейнера.
